# ADR-004: Контракт мастер-сида — диапазон и сериализация

## Status

Proposed (2026-07-31)

## Context

Инвариант **G7** (`design-and-release-supplement.md` §4.2) — «тот же seed → тот же граф» — один из восьми контрактов генератора и единственный, от которого зависит отладка по сиду («баг воспроизводится по сиду — бесценно», `godot-47-supplement.md` §11).

`godot-47-supplement.md` §11 предписывает `SeedService`, выдающий под-сиды (`graph_seed`, `loot_seed`, `combat_seed`) из мастер-сида. Но **диапазон мастер-сида и способ его сериализации нигде не зафиксированы**, а сейв обязан его нести: без мастер-сида нельзя восстановить граф при загрузке посреди экспедиции (точки записи — «после завершения узла», промт §14).

### Где ломается

API движка (`core/math/random_number_generator.h`):

```cpp
_FORCE_INLINE_ void set_seed(uint64_t p_seed) { randbase.seed(p_seed); }
_FORCE_INLINE_ uint64_t get_seed() { return randbase.get_seed(); }
```

Сид — **uint64**. Но при чтении из JSON любое число проходит через `double` (см. ADR-003), а у double 53 бита мантиссы. Прогон реальных значений:

```
                  seed |   после JSON-роундтрипа | ok?
      9007199254740991 |        9007199254740991 | OK    (2^53-1, последнее точное)
      9007199254740993 |        9007199254740992 | LOST  (2^53+1)
   8446744073709551615 |     8446744073709551616 | LOST  (типичный uint64)
```

Итог: если мастер-сид получен из `randomize()`, `hash64()`, `Time.get_unix_time_from_system()` в микросекундах или склейки `randi() << 32 | randi()`, то **после загрузки сейва сид другой** → под-сиды другие → граф перегенерируется другим → G7 нарушен.

Если сид получен из `randi()` (uint32, максимум ~4.29e9) — пронесёт, значение заведомо меньше 2^53.

### Почему это не поймает существующий тест

Sample-тест G7 из §4.3 гоняет генератор в памяти: `generate(s) == generate(s)`. Сериализация в него не входит, поэтому тест зелёный, а баг живой. Проявится как «после загрузки карта поехала» — то есть далеко от причины и через недели после написания кода.

## Decision

1. **Мастер-сид ограничен диапазоном `0 .. 2^53-1`** (`9007199254740991`). Это ровно граница точности double, поэтому значение переживает любой JSON-роундтрип без спецмер. Константа живёт в `SeedService`:
   ```gdscript
   const MAX_SEED: int = 9007199254740991  # 2^53-1 — предел точного double
   ```
2. **Генерация мастер-сида** — не `randomize()`/`hash64()` напрямую, а явное сведение в диапазон:
   ```gdscript
   func new_master_seed() -> int:
       var rng := RandomNumberGenerator.new()
       rng.randomize()
       return int(rng.randi()) << 21 | int(rng.randi() >> 11)  # 53 бита
   ```
   (точная формула — на усмотрение реализации; требование — результат `<= MAX_SEED`).
3. **Под-сиды не ограничены** этим диапазоном: они выводятся из мастер-сида детерминированно и **не сохраняются** — восстанавливаются при загрузке. В сейв едет только мастер-сид (+ индекс текущего узла).
4. **Сид, вводимый игроком** (daily seed / debug), нормализуется тем же кэпом при входе, а не при использовании.
5. **Тест-контракт G7 расширяется сериализацией.** Недостаточно проверять генератор в памяти:
   ```gdscript
   func test_seed_survives_save_roundtrip() -> void:
       var s := SeedService.MAX_SEED               # граничное значение
       var restored: int = load_seed(save_seed(s)) # через реальный JSON-путь
       assert(restored == s)
       assert(RouteGraph.generate(restored) == RouteGraph.generate(s))
   ```
   Граничные кейсы в наборе: `0`, `1`, `MAX_SEED`, `MAX_SEED - 1`.

## Consequences

### Positive

- G7 держится не только в юнит-тесте, но и на реальном пути «сохранил → загрузил → продолжил».
- Отладка по сиду работает как обещано в §11: сид из багрепорта воспроизводит карту точно.
- Кэп 2^53 бесплатен по энтропии: 9·10^15 вариантов графа — на порядки больше, чем игроки увидят.

### Negative

- Формально сужается пространство сидов против полного uint64. Практически незначимо, но правило надо помнить при вводе daily-seed извне.
- Ещё один инвариант, который легко нарушить, если кто-то позже напишет `rng.seed = hash(player_name)` мимо `SeedService`. Смягчение: генерация сида только через `SeedService`, прямые присваивания `rng.seed` вне него — повод для code-review.

## Alternatives considered

- **Хранить сид строкой** (`"seed": "8446744073709551615"`) — сохраняет полный uint64 и точен, но требует парсинга на каждом чтении и делает поле неудобным для ручной правки в отладке. Держим как запасной вариант, если когда-нибудь понадобится полный диапазон.
- **`JSON.from_native` для секции сида** — работает (целое кодируется как `"i:..."`, см. ADR-003), но ради одного поля тянуть другой формат сериализации избыточно.
- **Игнорировать** — отклонено: цена ошибки максимальна (тихая поломка ключевого инварианта жанра), цена фикса — одна константа.
