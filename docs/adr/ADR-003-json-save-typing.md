# ADR-003: Типизация сейвов — JSON теряет int при чтении

## Status

Proposed (2026-07-31)

> Нумерация: ADR-002 зарезервирован за открытым PR #2 («unstable loot rule»). Этот ADR — 003, чтобы не было коллизии при мёрже.

## Context

`docs/research/production-and-ai-workflow-supplement.md` §6.2 даёт референс-реализацию `SaveManager`, которую агент будет копировать дословно (документ прямо для этого написан). В ней есть ровно один каст типа:

```gdscript
var version: int = int(data.get("save_version", 1))
```

Все остальные поля читаются как есть. Это дефект, и он не косметический.

### Что именно происходит (проверено по исходникам движка)

**Запись целых — корректна.** В `core/io/json.cpp`, `JSON::_stringify()`:

```cpp
case Variant::INT:
    r_result += itos(p_var);   // int64 пишется точно, без double
```

**Чтение — разрушающее.** Там же, `JSON::_get_token()`:

```cpp
if (p_str[r_index] == '-' || is_digit(p_str[r_index])) {
    //a number
    const char32_t *rptr;
    double number = String::to_float(&p_str[r_index], &rptr);  // ВСЕГДА double
    r_token.type = TK_NUMBER;
    r_token.value = number;
```

Тип `TK_NUMBER` далее кладётся в результат без разбора целое/дробное (`_parse_value`: `r_value = r_token.value`). То есть **асимметрия**: `stringify` сохраняет `int`, `parse_string` возвращает `float` для всех чисел.

Это не баг, а следствие спецификации JSON (нет отдельного целого типа) и намеренное поведение — см. [godot#103801](https://github.com/godotengine/godot/issues/103801) на 4.4.stable:

```gdscript
print(JSON.parse_string(JSON.stringify({a: 1})))   # {a: 1.0}, не {a: 1}
```

### Почему это ломается тихо

`print()` часто показывает `2` вместо `2.0`, поэтому дефект не виден глазами. Ломается там, где GDScript различает типы:

- `match level: 2:` — не сматчится с `2.0`;
- значение как **ключ словаря** — `d[2]` и `d[2.0]` разные ключи;
- `Array.find(30)` вернёт `-1` (см. [godot-docs#3848](https://github.com/godotengine/godot-docs/issues/3848));
- сравнение `==` с целым литералом в ветвлениях.

Для этого проекта под ударом: `hub_state.modules[*].level`, счётчики четырёх ресурсов, `node_index` в `run_state`, любые enum-состояния, сохранённые числом.

### Готовое решение в движке

Godot имеет `JSON.from_native()` / `JSON.to_native()` — они сохраняют типы Variant при роундтрипе. По исходнику `JSON::_from_native()`:

```cpp
case Variant::INT: {
    return "i:" + String(p_variant);   // целое кодируется СТРОКОЙ
} break;
case Variant::FLOAT: {
    return "f:" + String(p_variant);
} break;
```

Целое едет как `"i:42"` — double его не касается вообще. Это официально рекомендованный путь: akien-mga в [godot#100454](https://github.com/godotengine/godot/pull/100454) отвечает на ровно эту жалобу словами «If you want to preserve Godot type information in JSON, the recommended way would be to use the new `JSON.from_native` and `JSON.to_native` methods».

Цена: файл перестаёт быть «красиво читаемым» (`{"level": "i:2"}` вместо `{"level": 2}`), что конфликтует с мотивацией «JSON ради читаемости» из ADR-001.

## Decision

**Гибрид — граница типов проходит по слоям, а не по всему файлу.**

1. **Конверт сейва пишется обычным `JSON.stringify`** — остаётся читаемым и diff-friendly.
2. **Каждое целое поле кастуется явно при чтении**, а не «доверяется» парсеру. Правило формулируется жёстко: *после `JSON.parse_string` ни одно число не используется напрямую — оно проходит через `int()` или `float()` осознанно.*
3. **Чтение идёт через типизированный DTO-слой**, а не по сырому `Dictionary`. Каждая секция (`profile`, `hub_state`, `run_state`, `settings`) получает `from_dict(d: Dictionary) -> XxxState` со статически типизированными полями. Касты живут в одном месте, и забыть их нельзя — иначе не скомпилируется присваивание в `int`-поле.
4. **`JSON.from_native`/`to_native` применяется точечно** — для секций, где типы разнородны и ручной каст нереалистичен (например, инвентарь модификаторов с Vector2/Color). Не для всего файла: читаемость важнее.
5. **Тест-контракт:** roundtrip-тест обязан проверять **типы**, а не только значения:
   ```gdscript
   var loaded := SaveManager.load_from_slot(0)
   assert(typeof(loaded.hub_state.modules["beacon"].level) == TYPE_INT)  # не TYPE_FLOAT
   ```
   Тест «значения совпали» такое пропустит, потому что `2 == 2.0` истинно.

Референс §6.2 в `production-and-ai-workflow-supplement.md` помечается ссылкой на этот ADR: копировать можно, но каст одного `save_version` — недостаточный образец.

## Consequences

### Positive

- Дефект ловится на этапе схемы, а не через месяц в виде «модуль 2 уровня ведёт себя как 1-го».
- DTO-слой заодно даёт валидацию повреждённых сейвов (промт §14 требует «обработку повреждённого файла») — одно место для обеих задач.
- Читаемость сейва сохраняется, экспорт/импорт для отладки (промт §14) остаётся人-читаемым.

### Negative

- DTO-слой — дополнительный код против «просто Dictionary», и его надо держать в синхроне со схемой при миграциях.
- Гибрид означает два способа сериализации в одной кодовой базе; граница должна быть явно описана, иначе через полгода никто не помнит, где какой.

## Alternatives considered

- **`JSON.from_native` для всего файла** — типобезопасно и без ручных кастов, но убивает читаемость и осмысленный `git diff` сейва; противоречит мотивации ADR-001.
- **Бинарная сериализация (`FileAccess.store_var`)** — сохраняет типы идеально и быстрее, но нечитаема, плохо мигрируется между версиями и противоречит промт-требованию «импорт/экспорт для отладки».
- **Ничего не делать, кастовать по месту** — то, что сейчас неявно предполагает референс §6.2. Отклонено: каст «по месту» забывается ровно в тех редких ветках, где потом ищут баг неделю.
