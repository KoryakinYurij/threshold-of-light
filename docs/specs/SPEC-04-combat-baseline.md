## 3. Разведчик (Scout)

`scenes/combat/player.tscn`, `CharacterBody2D`, слой `Player`.

| Параметр | Гипотеза | Обоснование |
|---|---|---|
| HP | 100 | Круглое число; делится на урон врага без остатка (см. §5) |
| Скорость | 220 px/c | Пересечение арены по короткой стороне (720 px) ≈ 3.3 c — читаемо, не «муха в банке» |
| Радиус хитбокса | 12 px | Greybox: круг |

**Дэш:**

| Параметр | Гипотеза | Обоснование |
|---|---|---|
| Дистанция | 160 px | ≈ 0.7 c обычного бега — ощутимый рывок, не телепорт |
| Длительность | 0.18 c | Ниже 0.2 c ощущается как «мгновенно» |
| i-frames | 0.18 c — **вся длительность дэша** | Правило читаемости: если неуязвимость короче анимации, игрок не может предсказать исход |
| Кулдаун | 0.8 c | Даёт ~1 дэш на атаку врага (см. §5) |

Решение по i-frames: неуязвимость **точно совпадает** с длительностью дэша. Частичные i-frames требуют визуального индикатора фазы, которого в greybox нет, — иначе игрок не может научиться.

**Снаряд** — числа **не дублируются здесь**. Единственный источник — `ModuleDefinition` Кузницы (SPEC-02 §3):

| Уровень Кузницы | Кулдаун | Пирсинг | Рикошеты |
|---|---|---|---|
| 1 | 0.35 c | 0 | 0 |
| 2 | 0.42 c | 1 | 0 |
| 3 | 0.47 c | 3 | 1 |

| Параметр снаряда | Гипотеза |
|---|---|
| Урон | 10 |
| Скорость | 600 px/c |
| Время жизни | 1.5 c |

`CombatDirector` читает уровень из `HubState.modules["forge_of_form"]` при входе на арену и берёт значения по индексу `level - 1`. **Своих копий этих чисел он не держит** — иначе acceptance №5 закрывается формально, а игра не меняется.

## 4. Преследователь

`scenes/combat/enemy_pursuer.tscn`, `CharacterBody2D`, слой `Enemy`. Поведение из промта §10: «идёт к игроку; простая атака в ближнем бою».

| Параметр | Гипотеза | Обоснование |
|---|---|---|
| HP | 30 | 3 попадания снарядом (10 урона) — читаемо на глаз |
| Скорость | 140 px/c | Медленнее разведчика (220) — кайтинг возможен, но требует места |
| Урон атаки | 25 | 4 попадания до смерти разведчика (HTK 4, жанровый коридор 3–6; ANSWERS Q-14 ⚠️) |
| Радиус атаки | 40 px | Ближний бой |
| Кулдаун атаки | 1.2 c | Даёт окно для дэша (кд 0.8 c) |

**Проверка бюджета:** 2 Преследователя × 30 HP = 60 HP. При кулдауне 0.35 c и уроне 10 — 6 попаданий ≈ 2.1 c чистого ДПС. Реальный узел с промахами и маневрированием — **60–90 c**, в бюджете §5.1. Элитный узел (3 врага, элитный ×2 HP) — **90–150 c** — свой коридор элитного узла (ANSWERS Q-12; §5.1).

Коэффициент глубины: HP и урон врага умножаются на `K(d) = (1 + 0.15)^d` (§5.2), `d` — глубина узла. На 6-м ряду ≈ ×2.3. Это же `K(d)` используется в G8 (SPEC-03 §4) — **одна формула, одно место в коде**.

## 5. FSM врага — разрешение противоречия

Принимается **5-состояний** из промта §10:

```
IDLE → SEEK → TELEGRAPH → ATTACK → RECOVER → SEEK
```

Обоснование: `TELEGRAPH` — не украшение, а несущее требование. Промт §12 запрещает наказывать игрока непрозрачной случайностью, а `design-and-release-supplement.md` §6.2 (адаптация «The Art of Screenshake») строит читаемость боя на предупреждении об атаке. Без `TELEGRAPH` дэш с i-frames 0.18 c становится угадыванием: игроку не на что реагировать. Урезанный вариант из `README.md` п.8 — это, по всей видимости, сокращение при переносе, а не решение.

**Действие:** `README.md` п.8 привести к 5 состояниям. Если владелец предпочтёт 4 — тогда i-frames дэша должны вырасти, а кулдаун атаки врага стать фиксированным и предсказуемым по таймеру; это другой дизайн боя, и его надо зафиксировать явно.

| Состояние | Длительность | Переход |
|---|---|---|
| `IDLE` | до обнаружения | игрок в радиусе 500 px → `SEEK` |
| `SEEK` | до сближения | дистанция ≤ 40 px → `TELEGRAPH` |
| `TELEGRAPH` | **0.5 c** | по таймеру → `ATTACK` |
| `ATTACK` | 0.15 c | по таймеру → `RECOVER` |
| `RECOVER` | 0.65 c | по таймеру → `SEEK` |

`TELEGRAPH` = 0.5 c (стартовое значение ANSWERS Q-14, слайдер F1 0.1–1.0) против кулдауна дэша 0.8 c: игрок успевает среагировать, но не может дэшить каждую атаку бесплатно. Полный цикл ≈ 1.3 c (0.5 + 0.15 + 0.65); кулдаун атаки из §4 (1.2 c) — соседняя гипотеза, калибруются в тикете 08.

Greybox-телеграф: смена цвета врага + рост масштаба. **Цвет не единственный признак** — требование промта §10 (различимость не только по цвету).

## 6. Матрица коллизий

|---|---|---|
| Scout (тело) | `Player` | `World`, `Enemy` |

Разделение hitbox/hurtbox — по `godot-47-supplement.md` §7. Правило: **hurtbox только принимает, hitbox только наносит**; один узел не совмещает роли.

## 7. AttackData

Контракт передачи урона. Не `int`, а ресурс — иначе i-frames, источник и отбрасывание расползутся по сигнатурам.

```gdscript
# scripts/combat/attack_data.gd
class_name AttackData extends RefCounted

var amount: int = 0
var source_id: String = ""      # стабильный runtime-ID атакующего
var knockback: Vector2 = Vector2.ZERO
var is_projectile: bool = false
```

`Hurtbox.take_hit(data: AttackData) -> void` — единственный путь урона в игре. `CombatDirector` подписан на попадания и владеет смертью и наградой; сами сущности своей смертью не распоряжаются («call down, signal up», `production-and-ai-workflow-supplement.md` §7.1).

## 8. Награды за узел

| Тип узла | Материалы | Нест. добыча | Воспоминания |
|---|---|---|---|
| `COMBAT` | 6–10 | 0 | 0 |
| `RESOURCE` | 12–18 | 0 | 0 |
| `ELITE` | 10–15 | **3–6** | 0–1 |
| `GUARDIAN` | 20–30 | **8–12** | 1 |
| `EVENT` / `CAMP` | 0–5 | 0 | 0 |

Сходимость с экономикой (`design-supp` §3.3): лёгкий забег 2–3 узла ≈ 20–35 Материалов ✔; глубокий 6–7 узлов с элиткой и guardian ≈ 60–100 ✔; Нест. добыча за забег 5–15 ✔. Числа подобраны так, чтобы попасть в этот спредшит, — он **канон**, эта таблица производна от него.

Ролевое правило (§3.1): Нестабильная добыча падает **только** с элиток и guardian. Её нельзя нафармить безопасно — иначе push-your-luck разваливается.

Разброс разыгрывается на `SeedService.loot_seed`, не на `combat_seed` — иначе число выстрелов в бою сдвинет лут (§11 правило 3).

## 9. Game feel — минимум Phase 1

Из чек-листа §6.2 в Phase 1 входят только те приёмы, что дают **читаемость**, а не сочность:

- [ ] Hit-stop 0.05 c при попадании (референс-код §6.3 `scripts/combat/hit_stop.gd`).
- [ ] Мигание врага при получении урона.
- [ ] Визуальный телеграф атаки (§5).
- [ ] Тряска камеры **только** на смерти врага, амплитуда малая (§6.3 `shake_camera.gd`).

Отложено: партиклы, эффект попадания, замедление времени, аудио (аудио — Phase 2 по `CONTEXT.md`).

Доступность (§6.4, «начинается в Phase 1»): тряска камеры должна отключаться флагом. Флаг живёт в настройках; сами настройки — Phase 2, поэтому в Phase 1 это константа в коде с явным `# TODO: вынести в настройки (SPEC-01 §9)`.

## 10. Definition of Done

- [ ] Разведчик двигается по WASD/стрелкам, стреляет, дэшит; дэш даёт неуязвимость ровно на 0.18 c.
- [ ] Преследователь проходит все 5 состояний; телеграф видим и **не только цветом**.
- [ ] Урон идёт исключительно через `Hurtbox.take_hit(AttackData)` — проверяется грепом на прямые `hp -=`.
- [ ] Смерть врага и смерть разведчика обрабатывает `CombatDirector`, не сами сущности.
- [ ] Боевой узел проходится за 60–120 c при обычной игре (замер на 5 прогонах, медиана).
- [ ] **Кузница ур.2: снаряд пробивает первого врага и наносит урон второму.** Тест — арена
      с двумя врагами в линию. Это acceptance №5; без этого теста он не закрыт.
- [ ] `K(d)` определён в одном месте и используется и боем, и G8 генератора.
- [ ] Лут разыгран на `loot_seed`: два прогона одного узла с разным числом выстрелов дают
      одинаковую награду.

## 11. Явные не-цели Phase 1

- Пульсатор и Собиратель — только Преследователь.
- Фазы у guardian (не-цель и остаются); в Phase 1 guardian = Преследователь со статистикой ×3 HP как потолком + один новый телеграфируемый паттерн и свой силуэт (ANSWERS Q-13).
- Аудио, партиклы, анимации, спрайты.
- Модификаторы, выбор оружия внутри забега.
- Пул объектов для снарядов — при 2 врагах не нужен.
