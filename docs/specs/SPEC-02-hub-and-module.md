## 1. Выбор единственного модуля: Кузница Формы

Из пяти MVP-модулей промта (§6) в Phase 1 реализуется **один**. Выбор — **Кузница Формы**.

Обоснование (это ответ на acceptance №5, а не вкусовщина): acceptance требует, чтобы улучшение модуля **изменило правило экспедиции**. Кузница — единственный из пяти модулей, чей эффект виден на арене в ту же секунду («изменение одной механики атаки», промт §6.3). Альтернативы проигрывают именно по проверяемости:

| Модуль | Почему не он в Phase 1 |
|---|---|
| Сердце Маяка | Даёт энергию и запуск экспедиции — это не «улучшение», а инфраструктура. Присутствует как объект, но не как апгрейдимый модуль. |
| Карта Трещин | Меняет генерацию графа — эффект виден только статистически, на глаз не проверяется. |
| Сад Памяти | Требует Воспоминаний и системы модификаторов — обе вне Phase 1. |
| Мастерская | Улучшает эвакуацию — эффект проявляется в редком краевом случае. |

## 2. Карточка модуля

Шаблон — `design-and-release-supplement.md` §3.4. Заполняется **до** реализации.

### Кузница Формы — уровень 1

| Поле | Значение |
|---|---|
| Что даёт (правило экспедиции) | Снаряд разведчика: базовый одиночный выстрел |
| Компромисс | — (базовый уровень, компромисса нет) |
| Цена | Бесплатно, построена на старте профиля |
| Когда берётся «правильно» | Всегда — стартовое состояние |
| Анти-синергия | — |

### Кузница Формы — уровень 2

| Поле | Значение |
|---|---|
| Что даёт (правило экспедиции) | **Снаряд пробивает первого врага и летит дальше** (пирсинг ×1) |
| Компромисс | Скорострельность −20% (кулдаун 0.35 c → 0.42 c) |
| Цена | **70 Материалов + 6 Нестабильной добычи** |
| Когда берётся «правильно» | После 2–3 успешных забегов |
| Анти-синергия | Против одиночных целей (элитка) чистый минус — пирсинг не срабатывает, а кулдаун вырос |

### Кузница Формы — уровень 3

| Поле | Значение |
|---|---|
| Что даёт (правило экспедиции) | Пирсинг ×3 + снаряд рикошетит от стен арены 1 раз |
| Компромисс | Скорострельность −35% от базы; снаряд может задеть разведчика на рикошете |
| Цена | **140 Материалов + 14 Нестабильной добычи** |
| Когда берётся «правильно» | При стиле «жадный дайвер» — окупается только на плотных узлах |
| Анти-синергия | На малой арене рикошет опаснее для игрока, чем для врага |

Цены — из спредшита `design-and-release-supplement.md` §3.3 (модуль ур.1/2/3 = 0/70/140 Материалов; ур.1 — стартовая постройка, бесплатна; уровни 2–3 дополнительно требуют Нестабильной добычи).

**Проверка «не фон»:** ни один уровень не описывается как «+X% к чему-то». Каждый меняет поведение снаряда, и у каждого есть уровень, на котором он **хуже** предыдущего.

## 3. ModuleDefinition (Custom Resource)

```gdscript
# scripts/hub/module_definition.gd
class_name ModuleDefinition extends Resource

@export var module_id: String = ""              # "forge_of_form" — стабильный ID, не локализуется
@export var display_name_key: String = ""       # ключ локализации (design-supp §8.1)
@export var max_level: int = 3
@export var socket_index: int = -1              # -1 = не размещён

## Индексируется уровнем-1: levels[0] — данные ур.1
@export var cost_materials: PackedInt32Array = []       # [0, 70, 140]
@export var cost_unstable_loot: PackedInt32Array = []   # [0, 6, 14]

## Правило экспедиции, которое даёт уровень
@export var projectile_pierce: PackedInt32Array = []    # [0, 1, 3]
@export var projectile_cooldown: PackedFloat32Array = []# [0.35, 0.42, 0.47]
@export var projectile_bounces: PackedInt32Array = []   # [0, 0, 1]
```

Ресурс живёт в `res://data/hub_modules/forge_of_form.tres`, редактируется в инспекторе.

**Правило единственного источника чисел** (`design-supp` §3.3): баланс лежит **либо** в `.tres`, **либо** в таблице — не в обоих. Канон — `.tres`; таблицы в `docs/` носят справочный характер и помечаются как таковые.

**Связь с боем:** `CombatDirector` при старте арены читает уровень модуля из `HubState.modules["forge_of_form"]` и применяет соответствующий индекс массива. Он **не** держит своих копий этих чисел (см. SPEC-04 §3).

## 4. Свет в Phase 1

Промт требует, чтобы модуль «занимал место или потреблял энергию». В Phase 1 действует **место**, а не энергия:

- Свет **не генерируется и не тратится**. Поля под него в `HubState` не заводятся.
- Ограничение — фиксированные сокеты вокруг маяка (§5).

Обоснование: потребление Света имеет смысл только при ≥2 конкурирующих модулях. При одном модуле это мёртвая механика, которую нечем проверить. Вводится в Phase 2 вместе со вторым модулем — тогда же появляется `SimulationClock` (SPEC-01 §1).

## 5. Компоновка хаба

**Фиксированные позиции сокетов, без drag-and-drop** (`CONTEXT.md`, Key decisions). Промт §7 требует drag-and-drop и соседские синергии — это **Phase 2**; при одном модуле синергии соседства не существует по определению.

```
scenes/hub/hub_screen.tscn
└── HubScreen (Control)
    ├── Lighthouse (Node2D)          — центр экрана, greybox: круг
    │   └── LighthouseLight (PointLight2D)
    ├── Sockets (Node2D)             — 4 фиксированные позиции
    │   ├── Socket0 (Marker2D)  pos (-200,   0)
    │   ├── Socket1 (Marker2D)  pos (   0,-160)
    │   ├── Socket2 (Marker2D)  pos ( 200,   0)
    │   └── Socket3 (Marker2D)  pos (   0, 160)
    ├── HubModuleView (Node2D)       — Кузница, инстанцируется в Socket0
    ├── ResourceBar (Control)        — Материалы, Нестабильная добыча
    └── ExpeditionButton (Button)    — эмитит EventBus.expedition_requested
```

Сокеты 1–3 в Phase 1 пусты и **видимы** — игрок должен видеть, что место есть. Кузница жёстко в `Socket0`.

**Визуальное изменение по уровню** (требование промта): greybox — смена цвета и масштаба `HubModuleView` по таблице `level → (Color, scale)`. Не спрайты; спрайты в Phase 2.

**Свет маяка:** `PointLight2D`, референс `design-and-release-supplement.md` §7.2. Glow/bloom в Compatibility **не работает** (§7.3, подтверждено godot#62110) — использовать additive-фейк, не пытаться включить glow в WorldEnvironment.

## 6. Поток апгрейда (acceptance №4)

```
Игрок жмёт Upgrade на HubModuleView
  → HubModuleView эмитит EventBus.module_upgrade_requested("forge_of_form")
  → ModuleSystem проверяет: level < max_level
                            HubState.materials      >= cost_materials[level]
                            HubState.unstable_loot  >= cost_unstable_loot[level]
  → при успехе: списывает ресурсы, HubState.modules["forge_of_form"] += 1
  → эмитит EventBus.module_built("forge_of_form", new_level)
  → HubModuleView перерисовывается; ResourceBar обновляется
  → эмитит EventBus.save_requested("hub")
```

`HubModuleView` **не мутирует** `HubState` — только эмитит (`CONTEXT.md`, Architecture rules).

При нехватке ресурсов кнопка неактивна, и рядом видна недостающая сумма. Промт §12 требует прозрачности: игрока нельзя наказывать непрозрачностью.

## 7. Definition of Done

- [ ] `HubScreen` открывается из `MainMenu`, виден маяк и Кузница в `Socket0`, три пустых сокета.
- [ ] `ResourceBar` показывает Материалы и Нестабильную добычу из `HubState`.
- [ ] При достаточных ресурсах апгрейд ур.1→ур.2 списывает ровно 70 Материалов и 6 Нест. добычи.
- [ ] При недостаточных — кнопка неактивна, недостающая сумма видна.
- [ ] После апгрейда `HubModuleView` **визуально изменился** (цвет/масштаб).
- [ ] После апгрейда сработал `save_requested("hub")` и слот содержит `"forge_of_form": 2`,
      причём значение типа `int`, не `float` (ADR-003).
- [ ] **Правило экспедиции изменилось:** на ур.2 снаряд разведчика в `CombatArena` пробивает
      первого врага и поражает второго. Проверяется тестом на арене с двумя врагами в линию.
      Это и есть acceptance №5 — без этого теста он не закрыт.

## 8. Явные не-цели Phase 1

- Drag-and-drop, перестройка, демонтаж, частичный возврат ресурсов.
- Соседские синергии и preview эффекта при размещении (нужны ≥2 модуля).
- Остальные 4 модуля, Свет, `PlacementSystem`.
- Спрайты и анимации — только greybox-геометрия.
