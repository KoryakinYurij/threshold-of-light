## 1. ⚠️ Открытое противоречие: что такое «7 узлов»

Документы допускают два несовместимых чтения, и аудит от 31.07 это не поймал.

**Чтение A — 7 узлов на всей карте.** Буквальное прочтение acceptance №2 («карта из 7 узлов») и `CONTEXT.md` («7-node graph»).

**Чтение B — 7 рядов глубины; игрок проходит 7 узлов, на карте их 12–17.** Прочтение `design-and-release-supplement.md` §4.1.

**Рекомендация: чтение B.** Основания — не вкусовые:

1. §4.1 перечисляет ряды явно: «ряд 0 = старт, ряды 1–5 = основные, ряд 6 = финал» — это 7 **рядов**.
2. §4.1 требует «2–3 видимых варианта за шаг». При 7 узлах суммарно и глубине 6 вариантов не остаётся: 1+1+1+1+1+1+1.
3. Инвариант **G4** («элитка не раньше глубины 3») требует глубины ≥ 4. При чтении A на глубину 3+ приходится 1–2 узла, и элитка почти всегда совпадает с финалом — инвариант вырождается.
4. §5.1 считает бюджет времени как «~1.5 мин × **6–7 узлов** + выбор ≈ 7–10 минут». Это длина **пути**, а не размер карты.
5. Инвариант **G6** («дети одного родителя — разных типов») предполагает, что у родителя ≥2 ребёнка. При чтении A ветвления почти нет.

Чтение A внутренне противоречиво: оно ломает G4 и G6 и делает «2–3 варианта за шаг» невыполнимым. Чтение B согласуется со всеми восемью инвариантами и с бюджетом времени.

**Требуется от владельца:** подтвердить чтение B. При подтверждении — завести **ADR-006**, а формулировку acceptance №2 в `README.md` уточнить до «карта глубиной 7 узлов (путь игрока — 7 узлов)». Остальная часть спеки написана под чтение B; при выборе A §2–§4 переписываются.

## 2. Структура графа

```
Ряд:      0      1      2      3      4      5      6
        START  [2-3] [2-3] [2-3] [2-3] [2-3]  GUARDIAN
```

- Ряд 0 — ровно 1 узел, тип `START`, всегда безопасен.
- Ряды 1–5 — по 2–3 узла (решает RNG генерации).
- Ряд 6 — ровно 1 узел, тип `GUARDIAN`.
- Итого 12–17 узлов; путь игрока — ровно 7.

Рёбра: узел ряда `d` соединяется с 1–3 узлами ряда `d+1`. **Пересечения рёбер запрещены** (§4.1, как в StS) — сохраняет читаемость карты. Формально: если `a < b` в ряду `d`, то у `a` нет ребра в узел с индексом бо́льшим, чем максимальный индекс-цель у `b`.

## 3. Алгоритм генерации (двухфазный)

`RouteGraph.generate(master_seed: int) -> RouteGraphData` — **чистая функция**, ноль узлов сцены. Живёт в `scripts/expedition/route_graph.gd`, тестируется без движковой сцены.

Использует **только** `SeedService.graph_seed(master_seed)`. Боёвка и лут работают на своих потоках и не могут сдвинуть последовательность (§11 правило 3).

### Фаза A — каркас путей

```
1. row_sizes[0] = 1; row_sizes[6] = 1
   row_sizes[1..5] = gen_rng.randi_range(2, 3)
2. Проложить 3 пути от START к GUARDIAN.
   Каждый шаг: из узла i ряда d в узел j ряда d+1, где |j_norm - i_norm| <= 1
   (нормализация индексов по размерам рядов — держит рёбра непересекающимися).
3. Гарантия ≥2 различных стартовых направлений: пути 1 и 2 обязаны выбрать
   разные узлы ряда 1. Если row_sizes[1] == 1 — недостижимо, но row_sizes[1] >= 2
   по построению.
4. Узлы, не попавшие ни на один путь, удаляются вместе с рёбрами.
```

### Фаза B — типы узлов

Взвешенное «ведро» (стартовая гипотеза, §4.1):

| Тип | Вес |
|---|---|
| `COMBAT` | 35% |
| `EVENT` | 20% |
| `RESOURCE` | 15% |
| `CAMP` | 10% |
| `EXTRACTION` | 10% |
| `ELITE` | 8% |

`START` и `GUARDIAN` фиксированы и в ведро не входят.

Правила-фильтры применяются **до** выбора; остаток добивается `COMBAT` (как StS добивает «типлесс»-комнаты монстрами):

- `ELITE` недоступен при `depth < 3` (G4).
- «Сильный» тип (`ELITE`, `CAMP`, `EXTRACTION`) недоступен, если родитель на этом пути того же типа (G5).
- Тип недоступен, если его уже взял сиблинг — узел того же ряда с общим родителем (G6).

### Валидация и повтор

```
attempt = 0
loop:
    data = build(derive(graph_seed, attempt))
    if validate_all_invariants(data): return data
    attempt += 1
    if attempt >= 32: push_error("generator broken"); return data
```

Повтор **детерминирован**: `attempt` входит в деривацию под-сида, поэтому один и тот же `master_seed` всегда даёт одну и ту же карту (G7 сохраняется). Это надёжнее, чем чинить граф на месте: инварианты остаются жёсткой проверкой, а не «пожеланием».

Счётчик `attempt > 0` логируется. Если в CI-прогоне доля повторов превышает 5%, генератор считается плохо настроенным — это сигнал править веса, а не поднимать лимит.

## 4. Инварианты (контракт для тестов)

Дословно из `design-and-release-supplement.md` §4.2:

```
G1. Граф связный: из старта достижим финал всегда.
G2. Нет тупиков без выбора (кроме финала): у каждого нефинального узла >=1 исходящего ребра.
G3. Минимум один маршрут содержит точку эвакуации не позже узла 3.
G4. Элитка не раньше глубины 3; guardian — только финал.
G5. Узлы одного «сильного» типа (элитка, лагерь, эвакуация) не идут подряд по пути.
G6. Дети одного родителя — разных типов.
G7. Тот же seed → тот же граф.
G8. Сложность не убывает с глубиной.
```

**Уточнение G8 (в §4.2 не формализовано):** сложность узла = `type_base × K(d)`, где `K(d) = (1 + 0.15)^d` (§5.2). База по типам: `RESOURCE`/`CAMP`/`EXTRACTION` = 0, `EVENT` = 1, `COMBAT` = 2, `ELITE` = 4, `GUARDIAN` = 6. G8 проверяется на **средних по ряду**: `mean(row_d) <= mean(row_{d+1})` для всех `d`. Это допущение спеки, а не цитата — при калибровке пересматривается.

**G3 после генерации не «чинится»** — карта без ранней эвакуации отбраковывается и пересоздаётся с `attempt+1`. Причина: точечная замена узла на `EXTRACTION` ломает G5/G6 и требует каскадной перепроверки.

## 5. Тесты генератора

`tests/unit/test_route_graph.gd`, GUT 9.7.1 (`godot_4_7`).

**Сида-контракт** (аудит §4): CI-гейт — **≥1000 сидов на каждый инвариант**; полный прогон **10 000 сидов** — перед этапными релизами, не на каждый коммит.

```gdscript
func test_same_seed_same_graph() -> void:
    assert_eq(RouteGraph.generate(42).serialize(), RouteGraph.generate(42).serialize())

func test_invariants_over_1000_seeds() -> void:
    for s in range(1000):
        var g := RouteGraph.generate(s)
        assert_true(g.is_connected(),                 "G1 @ %d" % s)
        assert_true(g.all_nonfinal_have_outgoing(),   "G2 @ %d" % s)
        assert_true(g.extraction_depth_min() <= 3,    "G3 @ %d" % s)
        assert_true(g.elite_min_depth() >= 3,         "G4 @ %d" % s)
        assert_true(g.no_repeated_strong_on_path(),   "G5 @ %d" % s)
        assert_true(g.siblings_distinct(),            "G6 @ %d" % s)
        assert_true(g.difficulty_nondecreasing(),     "G8 @ %d" % s)

func test_seed_survives_save_roundtrip() -> void:   # ADR-004 §5
    for s in [0, 1, SeedService.MAX_SEED - 1, SeedService.MAX_SEED]:
        var restored: int = load_seed(save_seed(s))
        assert_eq(restored, s)
        assert_eq(RouteGraph.generate(restored).serialize(), RouteGraph.generate(s).serialize())
```

**Анти-паттерн, который эти тесты закрывают** (§4.4): «валидация глазами в редакторе». Молчаливая регрессия генератора иначе гарантирована.

## 6. ExpeditionController

Владеет прохождением. Не знает про боевую арену — только про типы узлов.

```
expedition_requested (из хаба)
  -> master_seed = SeedService.new_master_seed()
  -> RunState.new(), GameState.current_run = run
  -> graph = RouteGraph.generate(master_seed)
  -> EventBus.expedition_started(master_seed)
  -> показать ExpeditionMap, подсветить доступных детей текущего узла

Игрок выбирает узел (2-3 варианта, кнопки — не свободная навигация по карте)
  -> RunState.current_node_index = выбранный
  -> EventBus.node_entered(index, type)
  -> COMBAT/ELITE/GUARDIAN -> SceneRouter в combat_arena.tscn
     RESOURCE/EVENT/CAMP   -> разрешается на месте, на карте
     EXTRACTION            -> предложить эвакуацию (§7)
  -> по завершении: RunState.pending_* += награды
  -> EventBus.node_cleared(index, rewards)
  -> EventBus.save_requested("node_cleared")
```

**UI-контракт карты** (пробел, закрываемый этой спекой): игрок видит **весь граф** сразу — это «обещание честного выбора» из §1.1. Доступны для клика **только** дети текущего узла. У каждого доступного узла подписан тип и оценка угрозы («2 врага», «вероятна элитка») — промт §12 запрещает наказывать игрока непрозрачной случайностью. Пройденный путь подсвечен.

## 7. ExtractionSystem

Единственные выходы из экспедиции в Phase 1: **узел эвакуации**, **победа над guardian**, **смерть**. Досрочный выход не из точки эвакуации **не вводится** (ADR-002).

На узле `EXTRACTION` игрок получает выбор с явными цифрами: сколько уносит сейчас и что теряет при смерти, если пойдёт дальше.

Перенос наград по таблице ADR-002:

| Исход | Материалы, Воспоминания | Нестабильная добыча |
|---|---|---|
| Эвакуация на узле эвакуации | 100% | **100%** |
| Победа над guardian | 100% | 100% |
| Смерть | Материалы 100%, Воспоминания ~50% | **0%** |

```
Эвакуация:
  HubState.materials      += RunState.pending_materials
  HubState.unstable_loot  += RunState.pending_unstable_loot
  ProfileState.memories   += RunState.pending_memories
  ProfileState.runs_completed += 1
  GameState.current_run = null
  EventBus.extraction_completed(rewards) -> save_requested("extraction") -> SceneRouter в хаб

Смерть:
  HubState.materials      += RunState.pending_materials
  ProfileState.memories   += int(RunState.pending_memories * 0.5)
  pending_unstable_loot отбрасывается
  ProfileState.runs_died += 1
  GameState.current_run = null
  EventBus.scout_died(index) -> save_requested("death") -> SceneRouter в хаб
```

## 9. Явные не-цели Phase 1

- Свободная навигация по карте, зум, панорамирование.
- Содержательные события (`EVENT` в Phase 1 = плоская выдача ресурса с текстом-заглушкой).
- Модификаторы после узлов (`ModifierSystem`).
- Собиратель как угроза нестабильной добыче (SPEC-04 §8).
- Эскалация «мягкое давление времени» из §5.2.
