# Уроки сессии T-03 (обязательны к прочтению перед работой)

Этот файл — результат разбора сессии T-03 (бой и панель тюнинга).
Он зафиксировал то, что реально замедляло работу и портило качество.
AGENTS.md ссылается на него как на обязательный первый шаг.

---

## Правило 5 минут (самое важное)

**Проблема:** В сессии T-03 проблема с передачей файлов решалась перебором
кавычек ~40 минут. Свежий взгляд (ревьюер) предложил бы обход (scp) за пару минут.

**Правило:** Если задача или подзадача не решается дольше ~5 минут — перестань
перебирать варианты в одиночку и подключи независимого ревьюера / второго агента:
`antigravity-cli` (скилл есть), `code-reviewer-deepseek-flash`, `code-review`.
Новый взгляд почти всегда быстрее N-ной попытки того же подхода.

## Урок 1. Сначала читай локальные скиллы проекта

**Проблема:** В проекте есть `.agents/skills` с профильными Godot-скиллами
(godot-combat-system, godot-input-handling, godot-state-machine-advanced и др.).
Их паттерны указали бы правильную архитектуру урона с первого раза. Начав без них,
я переделал бой (DamageData -> Hurtbox -> HealthComponent) и поймал баги
(мониторящийся хёртбокс, monitorable), которые скилл запрещал заранее.

**Принцип:** Перед реализацией читай локальные скиллы/инструкции проекта
(`.agents/skills`, `AGENTS.md`). Сначала контекст проекта, потом код.

---

## Урок 2. Не борись с кавычками — смени механизм передачи

**Проблема:** Передача файлов на Windows через ssh-цепочку (bash -> OpenSSH ->
cmd/PowerShell) с путями, содержащими пробелы, сожгла больше всего времени:
кавычки системно срезались на слоях, `$` ломались. Перебор комбинаций кавычек
не работал.

**Принцип:** Для передачи файлов в многослойной ssh-цепочке: пиши файл локально,
scp в промежуточный каталог **без пробелов** (напр. `C:\Users\Fixed\`), затем
`cmd /d /c "cd /d <цель> && move /y <промежуточный> <относительный_путь>"`.
Относительные пути без кавычек. Один раз отладил — повторяй.

## Урок 3. В Godot 4 новые class_name-скрипты не видны headless без `--import`

**Проблема:** После добавления скриптов с `class_name` headless-запуск падал с
«Could not find type "X" in the current scope», хотя код был верен. Глобальный
кеш классов не пересобирается сам.

**Принцип:** После добавления/переименования `class_name`-скрипта выполняй
`godot --headless --path . --import`, затем запускай headless-тесты. Ошибки
«Could not find type» при корректном коде — почти всегда кеш, а не код.

## Урок 4. Свойства из сцены молча игнорируются без `@export`

**Проблема:** В `.tscn` врагу задано `maximum = 30`, но поля не были `@export` —
Godot создал мёртвые динамические свойства, реальные остались с дефолтом 100.
Враги имели 100 HP вместо 30 (10 ударов вместо 3). Баг прошёл все проверки,
поймал только code-review.

**Принцип:** Значения, приходящие из сцены/инспектора, объявляй как `@export`.
Иначе сцена молча задаёт несуществующее свойство, а скрипт работает с дефолтом.

## Урок 5. Юнит-тесты и headless-запуск не заменяют функциональный smoke-тест

**Проблема:** Тесты проекта (75/75) и headless-запуск были зелёными, но реальный
бой не работал: урон от мели не доходил, HP врагов неверное. Поймал только
smoke-тест, который инстанцирует арену, бьёт скаутом и проверяет **абсолютные**
значения (30 -> 20, 100 -> 75, HP врага == 30).

**Принцип:** Пиши маленький smoke-тест реального сценария (удар -> урон ->
смерть) и проверяй абсолютные значения, а не только «изменилось ли что-то».
Абсолютные проверки ловят баги дефолтов и молчаливой конфигурации.

---

## Урок 6. Ревью — обязательный этап перед коммитом

**Проблема:** Баг HP врагов (100 вместо 30) прошёл юнит-тесты, headless и
smoke-тест с проверкой «урон уменьшился». Поймал его только независимый
code-review, специально искавший несоответствия сцены и скрипта.

**Принцип:** Перед коммитом запускай независимое ревью изменений с фокусом на
стыки: сцена <-> скрипт, конфиг <-> код, слои/маски физики. Тесты проверяют
поведение, ревью — соответствие задуманному.
