# REPORT T-03 — Бой и панель тюнинга

Ветка: `прототип-дипсик`. Предыдущая точка: T-02 закрыт (5fd8de7).

## Что сделано

- **Скаут (CharacterBody2D):** WASD-движение, атака (ЛКМ), дэш (Space) с окном
  неуязвимости. Буфер ввода 0.18 с на дэш и атаку (Q-03).
- **Враг-преследователь:** плоский FSM `IDLE -> SEEK -> TELEGRAPH -> ATTACK ->
  RECOVER` (спека T-03 / SPEC-04), телеграф атаки с визуальным предупреждением,
  урон по скауту, смерть.
- **Урон по архитектуре godot-combat-system:** `DamageData` (RefCounted) ->
  `MeleeHitbox` (Area2D, активен только в swing-окне) -> `Hurtbox.take_attack`
  -> `HealthComponent.take_damage` (i-frames в компоненте). HUD слушает
  `health_changed`/`died` (signal up / call down).
- **Game feel:** hit-stop через `Engine.time_scale` (PROCESS_MODE_ALWAYS +
  unscaled-delta), screenshake (trauma -> Camera2D.offset), input buffer.
- **Смерть скаута:** панель «SCOUT DOWN», R — перезапуск арены. Без T-04
  (нет карты экспедиции, extraction, death-loss, игровых точек сохранения).
- **F1-панель:** 6 ползунков (i-frames, кулдаун дэша, телеграф, урон врага,
  HP скаута, скорость), применяются на лету, сохраняются через `SettingsStore`
  (`user://settings.cfg`, секция `combat`).
- **Интеграция:** кнопка «Тестовый бой (T-03)» в хабе -> `EventBus.combat_requested`
  -> `SceneRouter` -> арена. `AGENTS.md`: обязательный первый шаг «load project
  skills» из `.agents/skills`.

## Решения (блокеры, решены ресёрчем, без вопросов владельцу)

1. **Интеграция входа в бой:** арена доступна напрямую из хаба кнопкой
   «Тестовый бой» через новый `EventBus.combat_requested` (T-04 добавит
   нормальный вход через карту экспедиции). Так T-03 можно щупать сразу.
2. **Мели-атака вместо снарядов:** SPEC-04 описывает снаряды от Forge of Form;
   для T-03 достаточно мели с окном попадания (ближе к первому ощущению боя,
   проще тюнить). Снаряды — T-06.
3. **i-frames дэша и урона разделены:** компонентный i-frame (0.12 с после
   попадания) + дэш-i-frames (0.18 с по ползунку) — чтобы ползунок влиял
   именно на дэш, а не на общий иммунитет.
4. **Глобальные class_name регистрируются через `godot --headless --path . --import`** —
   headless-запуск без этого не подхватывает новые классы; `--import` входит в
   tools\build.cmd, а .godot-кеш вне git.
5. **Кодировка и перенос:** файлы переносились через scp + move (cmd-кавычки
   с пробелами ненадёжны в этой цепочке ssh); русские строки в UI валидны в UTF-8.

## Хотфикс после ручной проверки (баг-репорт владельца)

Владелец сообщил: «враг не умирает с 3 ударов». Диагностика (headless-сцена
`tests/combat_diag`, реалистичный бой с активной погоней) показала, что при
дефолтах **и при сохранённых настройках владельца** враг (30 HP) умирает ровно
с 3 ударов мели (10 урона): 30->20->10->смерть. Exe пересобран после фикса
HP (таймстемп exe > таймстемп health_component.gd), т.е. бинарь не устарел.

Вывод: механика корректна; причина ощущения «не умирает» — промахи ударов
(радиус мели ~80 px и окно 0.1 с; при скорости 400 px/s и атаке мышью часть
свингов уходит мимо/не в сторону врага) плюс мгновенное исчезновение врага
(`queue_free`) без видимого фидбэка. Исправления:

1. **Надёжность мели:** радиус хитбокса 30->36, офсет 34->38 (досягаемость
   ~80->90 px), swing-окно 0.1->0.14 с.
2. **Видимая смерть врага:** вместо мгновенного `queue_free` — фейд-аут 0.28 с
   с расходящимся кольцом; на килл добавлен мини-hit-stop (0.06 с) + screenshake
   (`notify_enemy_died` -> `emit_feedback`), чтобы смерть читалась.
3. **Баг слайдера HP скаута:** `scout._ready` выполняется раньше `arena._ready`
   (дети готовы раньше родителя), поэтому `scout_hp` из settings.cfg не
   применялся при загрузке (скаут всегда стартовал со 100 HP). Теперь максимум
   HP применяется отложенно (`call_deferred`) и повторно по сигналу
   `tuning_changed` — ползунок честно работает «на лету».
4. **Регресс-тест:** в `tests/combat_smoke.tscn` добавлена проверка
   «3 удара = смерть» (30->20->10->dead).
