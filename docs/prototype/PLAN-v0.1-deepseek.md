# Прототип v0.1 — план работ (ветка `прототип-дипсик`)

> Этот план написан агентом Buffy для исполнителя (DeepSeek) и живёт в ветке
> `прототип-дипсик`. Это **не копия** `docs/prototype/TASKS-v0.1.md` из ветки
> `proto/v0.1` — свой план. Из чужого взята только сильная логика: порядок
> задач по «что владелец может пощупать», ресёрч вместо вопросов владельцу,
> один таск = один чат, честный финальный отчёт.

## Цель

Дать владельцу **пощупать** игру руками, чтобы у него появилось мнение по
14 дизайн-развилкам из `docs/design/OPEN-QUESTIONS.md`. Ветка одноразовая:
в `master` вернутся только выводы (ответы, калиброванные числа, отчёт), не код.

## Окружение (проверено замерами 2026-08-02)

| Параметр | Значение |
|---|---|
| Машина | Linux VPS, headless, **1 CPU**, ~2 ГБ RAM |
| Память сейчас | занято ~1.4 ГБ (claude + freebuff + hermes + context-mode), свободно ~570 МБ, swap 2 ГБ (1.7 свободно) |
| Godot | `/home/fixedius/bin/godot` → 4.7.1.stable.official (пин ADR-001 совпадает) |
| Проект | уже импортирован: `.godot/` существует, импорт инкрементальный |
| Холодный импорт | пик **~650 МБ** RSS, ~6 сек (только при первом импорте) |
| Запуск сцены headless | пик **~100–150 МБ** RSS |

### Правила запуска Godot

1. **Один инстанс за раз.** Параллельных импортов/запусков не делать — 1 CPU.
2. Холодный импорт (650 МБ) при занятых ~1.4 ГБ уйдёт в swap на несколько
   секунд — это нормально, не паника. Рабочие запуски (~100–150 МБ) в swap
   не идут.
3. Стандартная проверка таска: `godot --headless --path . --quit-after 60`
   — чистый выход без ошибок скриптов/сцен. Экрана нет, визуал проверяет
   владелец.
4. Кодировку не трогаем (Linux, UTF-8 по умолчанию; правило `chcp 65001`
   из чужого плана относится к Windows-машине владельца).

## Правила для всех чатов по этой ветке

1. **Владельца не спрашивать.** Блокер → ресёрч: как это решают профессионалы
   в жанре (Hunt: Showdown, Slay the Spire, Hades, Dead Cells и т.п.), выбрать
   по балансу качество/трудозатраты, записать решение **с источниками**.
   Не «на усмотрение владельца», не «оставим TODO».
2. **Один таск = один чат.** Контекст не тянет больше.
3. **Один таск = один коммит** с внятным сообщением. Незавершённый таск
   не закрывать.
4. **Соблюдать:** ADR-003 (JSON: целые поля кастовать явно), ADR-004
   (мастер-сид ≤ 2^53−1), ADR-005 (автолоады без `class_name`), именование
   из `CONTEXT.md`.
5. **В `master` ничего не мержим** из этой ветки.
6. Каждый таск после T-02 заканчивается готовностью к сборке для владельца:
   `export_presets.cfg` (Windows) + `tools/build.cmd`. Сама сборка `.exe`
   запускается на машине владельца (Windows, `D:\Tools\Godot\4.7.1\godot.cmd`)
   — на VPS её не выполнять, только подготовить.

## T-01 — Ответы на 14 вопросов через ресёрч

**Зачем.** Все таски блокированы `docs/design/OPEN-QUESTIONS.md` (13 открытых,
1 калибровка). Владелец ответить не может — отвечает ресёрч, а не вкус агента.

**Что сделать.** По каждому Q-01…Q-14: найти, как эту же развилку решают
в шипнутых играх жанра, и выбрать. Опорные ориентиры (не догма):
- extraction risk/reward — Hunt: Showdown, Tarkov, Dark and Darker
- структура забега и выбор пути — Slay the Spire, Hades, Inscryption
- ощущение боя, i-frames, телеграф — Hades, Hollow Knight, Dead Cells
- рост сложности по глубине — Risk of Rain 2, StS act scaling
- экономика хаба — Hades (Зеркало), Dead Cells, Rogue Legacy

**Результат:** `docs/prototype/ANSWERS-v0.1.md`. На каждый вопрос:
выбранный вариант · ≥2 внешних источника · почему для нас · цена разворота ·
**чем проверяется в билде** (какой ползунок, какой замер).
В `OPEN-QUESTIONS.md` (только в этой ветке) статус → `гипотеза-прототипа`
со ссылкой на ANSWERS. Не `решён` — `решён` = ответ владельца.

**Готово, когда:** 14/14 закрыты, ни одного «зависит от», у каждого есть
источники и способ проверки.

**Не делать:** не трогать `SPEC-01…04`, `docs/adr/`, `README.md`.

## T-02 — Каркас и пайплайн

**Что сделать.** Автолоады `GameState`, `EventBus`, `SeedService` без
`class_name` (ADR-005). Состояния раздельно: `RunState`, `HubState`,
`ProfileState` (без God object). `SaveManager`: JSON через `FileAccess`,
атомарная запись, 3 слота, бэкап, типизированный DTO-слой (ADR-003);
настройки — `ConfigFile`. Сид ≤ 2^53−1, суб-сиды выводные (ADR-004).
`export_presets.cfg` (Windows) + `tools/build.cmd`.

**Готово, когда:** `godot --headless --path . --import --quit` без ошибок
(инкрементальный, лёгкий) · тест save/load round-trip зелёный · build.cmd
проверен синтаксически, запуск `.exe` — на машине владельца.

**Не делать:** геймплея и арта. Заглушка вместо сцены — норма.

## T-03 — Бой и панель тюнинга (первое, что щупают)

**Зачем.** Q-02 и Q-03 — про ощущение, текстом не закрываются.

**Что сделать.** Скаут `CharacterBody2D`: WASD, дэш с окном неуязвимости,
атака. Враг: FSM с телеграфом по Q-02, урон, смерть, преследование.
Камера, попадания, смерть скаута. Game feel: hit-stop, screenshake,
буфер ввода. **F1-панель:** ползунки на i-frames дэша, кулдаун, длину
телеграфа, урон, HP, скорость; значения применяются на лету, состояние
панели сохраняется.

**Готово, когда:** headless-запуск чистый; есть Windows-сборка, где можно
минуту драться и крутить ползунки. В отчёте — дефолты и почему.

## T-04 — Экспедиция

**Что сделать.** Граф узлов по Q-01, выбор из 2–3 вариантов, типы узлов
(бой, ресурс, событие, лагерь, эвакуация, элита, страж), эвакуация с
порогом (Q-06), смерть и потери (Q-05), стабильная/нестабильная добыча,
элита (Q-12), Guardian (Q-13), воспроизводимость по сиду.

**Готово, когда:** полный забег от входа до эвакуации/смерти, результат
корректно ложится в `RunState` и переживает сохранение; тот же сид → та же карта.

## T-05 — Хаб и экономика (петля замыкается)

**Что сделать.** Экран хаба, Маяк, 4 сокета (Q-10), Кузница 3 уровня с
минусами (Q-07), стоимости (Q-08), Свет (Q-09), Материалы, Память как
валюта разблокировок. Модули **меняют правила экспедиции**, не только числа.

**Готово, когда:** забег → добыча → постройка → следующий забег **ощутимо
другой**. Модуль, не меняющий игру, — не сделан.

## T-06 — Headless-симулятор и калибровка

**Что сделать.** Симулятор забегов без графики, бот-политика
(жадный/осторожный/случайный): доля успешных эвакуаций по глубине,
средняя/медианная добыча, дисперсия, длина забега в минутах, проверка
кривой K(d). Запуск: `godot --headless --script tools/sim.gd -- --runs 1000`.

**Готово, когда:** печатает таблицу · числовой пакет Q-14 подобран по
замерам, а не выдуман · в отчёте видно, где предположения T-01 не подтвердились.

## T-07 — Полировка, сборка v0.1, отчёт

**Что сделать.** Полировка ощущения по итогам T-03…T-06, главное меню →
хаб → экспедиция → возврат без разрывов, финальная Windows-сборка,
`docs/prototype/REPORT-v0.1.md` (в этой же ветке).

**Отчёт честно разделяет:** 1) подтверждено замером, 2) выбрано по практике
жанра, но не проверено, 3) осталось на вкус владельца.

**Готово, когда:** `.exe` запускается с чистой машины, отчёт написан, ветка запушена.
