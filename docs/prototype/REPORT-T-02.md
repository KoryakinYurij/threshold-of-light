# T-02 — Каркас и пайплайн

Дата: 2026-08-02  
Ветка: `прототип-дипсик`

## Сделано

- Добавлены автолоады в порядке SPEC-01 §1: `EventBus`, `SeedService`,
  `GameState`, `SaveManager`, `SceneRouter`.
- Автолоады не объявляют `class_name` (ADR-005).
- Состояние разделено на `RunState`, `HubState`, `ProfileState`; `GameState` не
  стал God object.
- Реализован `SeedService` по ADR-004: мастер-сид `0..2^53-1`, независимые
  выводные потоки `graph_seed` / `loot_seed` / `combat_seed`, под-сиды в сейвы
  не пишутся.
- Реализован typed DTO-слой `SaveSchema` по ADR-003: integer-поля явно
  кастуются при чтении JSON.
- Реализован `SaveEnvelope` v1 и `SaveManager`: JSON через `FileAccess`,
  атомарная запись `.tmp → rename`, `.bak`, 3 слота, fallback на backup при
  повреждении основного файла, загрузка/создание профиля.
- Backup-copy проверяется: при ошибке создания `.bak` временный файл удаляется,
  а существующий слот не заменяется.
- Добавлен `SettingsStore` на `ConfigFile`; настройки отделены от сейвов.
- Меню запускает игру через `EventBus`; `SceneRouter` переводит его в
  hub-заглушку.
- Добавлена hub-заглушка для проверки маршрута сцен.
- Добавлены `export_presets.cfg`, `tools/build.cmd`, `tools/test.cmd` и инструкция
  `docs/prototype/BUILD.md` для Windows-сборки.
- Добавлен headless test runner `tests/run_tests.tscn` и 72 проверки.

## Проверки на VPS

Эти прогоны — историческая проверка T-02. VPS больше не является рабочей средой
проекта.

```bash
godot --headless --path . --import --quit
godot --headless --path . res://tests/run_tests.tscn
```

Результат: импорт `exit 0`; тесты `exit 0`, `ЗЕЛЕНО: 72 проверок пройдено`.

Покрыто тестами:

- регистрация и порядок автолоадов;
- отсутствие `class_name` у автолоадов;
- диапазон, детерминизм и независимость потоков сидов;
- JSON round-trip для profile/hub/run;
- сохранение типов `int`, `PackedInt32Array`, `PackedStringArray`;
- граничные сиды `0`, `1`, `MAX_SEED-1`, `MAX_SEED`;
- атомарная запись, `.tmp`, backup и восстановление из backup;
- настройки через `ConfigFile`;
- маршрут `StartButton → EventBus → SceneRouter → HubScreen`.

Ожидаемое предупреждение при восстановлении из backup означает, что повреждённый
основной JSON отвергнут и успешно загружен backup.

Точки сохранения `node_cleared`, `extraction` и `death` будут покрыты отдельными
интеграционными тестами в T-04, когда появятся `ExpeditionController` и
`ExtractionSystem`. В T-02 проверены общий run-state round-trip и hub-state
сохранение; несуществующий пока геймплей не имитируется фиктивными тестами.

## Важная особенность headless-прогона

Headless Godot не завершается сам после запуска обычной сцены. Тестовый раннер
обязан явно вызвать `get_tree().quit()` после вынесения вердикта. В T-02 это
закрыто корневым `SceneFlowProbe`, который переживает смену current scene и
завершает процесс с кодом теста. Сам переход `MainMenu → HubScreen` подтверждён
в headless-тесте.

## Переход на Windows и следующая сессия

После завершения T-02 **вся дальнейшая разработка ведётся только на Windows**:
кодирование, запуск Godot, ручная проверка, тесты, визуальная отладка и экспорт.
VPS не используется для продолжения задач. Результаты VPS-прогонов выше — только
историческая проверка T-02.

Рабочая копия проекта на Windows:

```text
D:\Code AI\Games\Godot v1
```

Первая Windows-сессия:

1. Открыть PowerShell в `D:\Code AI\Games\Godot v1` и выполнить `git status` до
   любых переключений.
2. Зафиксировать текущую ветку и проверить незакоммиченные изменения.
3. Если дерево чистое — переключиться на `прототип-дипсик`; если нет — сначала
   безопасно сохранить изменения, ничего не удаляя.
4. Убедиться, что присутствует коммит T-02 из этой ветки.
5. Запустить Godot 4.7.1 в оконном режиме и проверить `MainMenu → HubScreen`,
   создание/загрузку сейва, `tools\test.cmd`, `tools\build.cmd` и запуск `.exe`.
6. Только после этой проверки переходить к следующему тикету.

Для новых чатов рабочее правило: начинать работу из Windows-копии по этому пути;
не продолжать реализацию на VPS и не переносить рабочий процесс обратно на VPS.

API-соглашение T-02: `GameState.begin_run()` или `begin_run(-1)` создаёт новый
мастер-сид; внешний daily/debug-сид передаётся неотрицательным числом и
нормализуется через `SeedService.normalize()`.
