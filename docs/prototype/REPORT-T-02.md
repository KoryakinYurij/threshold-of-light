## Проверки на VPS

Команда импорта:

```bash
godot --headless --path . --import --quit
```

Результат: `exit 0`, ошибок импорта и parse errors нет.

Тесты:

```bash
godot --headless --path . res://tests/run_tests.tscn
```

Результат: `exit 0`, `ЗЕЛЕНО: 72 проверок пройдено`.

Покрыто тестами:

- регистрация и порядок автолоадов;
- отсутствие `class_name` у автолоадов;
- диапазон, детерминизм и независимость потоков сидов;
- JSON round-trip для profile/hub/run;
- сохранение типов `int`, `PackedInt32Array`, `PackedStringArray`;
- граничные сиды `0`, `1`, `MAX_SEED-1`, `MAX_SEED`;
- атомарная запись, `.tmp`, backup и восстановление из backup;
- настройки через `ConfigFile`;
- маршрут `StartButton → EventBus → SceneRouter → HubScreen`.

Ожидаемое предупреждение в тесте восстановления из backup:
повреждённый основной JSON отвергается, после чего загружается backup. Это
проверяемое поведение, а не ошибка теста.

## Важная особенность headless-прогона

Headless Godot не должен сам завершаться после запуска обычной сцены. Тестовый
раннер обязан явно вызвать `get_tree().quit()` после вынесения вердикта. Поэтому
минимальный запуск сцены без финального `quit` может выглядеть как зависание,
даже если код уже отработал. В T-02 это закрыто корневой `SceneFlowProbe`, который
переживает смену current scene и завершает процесс с кодом теста. Сам переход
`MainMenu → HubScreen` подтверждён в headless-тесте.

## Что проверить на Windows в следующей сессии

1. Открыть рабочую копию и выполнить `git status` до любых переключений.
2. Зафиксировать текущую ветку и проверить, есть ли незакоммиченные изменения.
3. Если дерево чистое — переключиться на `прототип-дипсик`; если нет — сначала
   безопасно сохранить изменения, ничего не удаляя.
4. Убедиться, что присутствует коммит T-02 из этой ветки.
5. Запустить Godot 4.7.1 в оконном режиме и проверить:
   - `MainMenu → HubScreen`;
   - создание/загрузку сейва;
   - `tools\test.cmd`;
   - `tools\build.cmd` и запуск `.exe`.
6. Только после этой проверки переходить к следующему тикету.

Следующая рабочая среда: **Windows**, а не VPS. VPS остаётся средой для
текстовых проверок и headless-регрессий, но визуальная проверка, ручной прогон
и экспорт выполняются на Windows-машине владельца.
