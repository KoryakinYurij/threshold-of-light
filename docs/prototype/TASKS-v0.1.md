# Прототип v0.1 — план работ

Ветка: `proto/v0.1`. Цель прототипа — **дать владельцу пощупать**, а не построить фундамент.
Владелец сейчас не может ответить на дизайн-вопросы, потому что ему не с чем сверяться.
Мнение появится от рук на клавиатуре. Всё остальное подчинено этому.

**Один таск = один чат.** Контекст не тянет больше.

---

## Правила для всех чатов по этой ветке

1. **Владельца не спрашивать.** Упёрся в блокер — идёшь в интернет, смотришь, как это
   решают профессиональные геймдевы в шипнутых играх, выбираешь по балансу
   качество/трудозатраты, записываешь решение с источниками. Не «на усмотрение
   владельца», не «оставим TODO».
2. **Ветка одна — `proto/v0.1`.** В `master` ничего не мержим. Прототип одноразовый:
   обратно поедут только выводы, не код.
3. **Начиная с T-02 каждый таск заканчивается свежим `.exe`.** Владелец должен иметь
   возможность запустить и потрогать после любого шага.
4. **Godot:** `D:\Tools\Godot\4.7.1\godot.cmd`. Работа через `--headless` — MCP-сервер
   `godot-mcp` по SSH недоступен, экрана агент не видит. Визуальная проверка на владельце.
5. **Кодировка:** `chcp 65001` перед запуском Godot, иначе русские логи в cmd.exe поедут.
6. **Соблюдать:** ADR-003 (JSON: каждое целое поле кастовать явно), ADR-004 (мастер-сид
   ≤ 2^53−1), ADR-005 (автолоады **без** `class_name`), правила именования из `CONTEXT.md`.
7. **Каждый таск — коммит с внятным сообщением.** Незавершённый таск не закрывать.

### Шаблон запуска нового чата

```
Проект: D:\Code AI\Games\Godot v1 на моём Windows (SSH с VPS через туннель).
Ветка proto/v0.1. Прочитай docs/prototype/TASKS-v0.1.md, раздел T-0X.
Выполняй его целиком, меня не спрашивай: на каждый блокер ищешь, как это делают
профи, выбираешь и делаешь. В конце — отчёт и свежий билд.
```

## T-01 — Ответы на 14 вопросов через ресёрч

**Зачем.** Все остальные таски заблокированы `docs/design/OPEN-QUESTIONS.md`:
13 вопросов `открыт`, один `калибровка`. Владелец ответить не может. Значит отвечает
ресёрч, а не вкус агента.

**Что сделать.** По каждому Q-01…Q-14: найти, как эту же развилку решают в шипнутых
играх жанра, и выбрать. Опорные ориентиры для поиска (не догма, ищи шире):

- extraction risk/reward, что теряется при смерти — Hunt: Showdown, Escape from Tarkov, Dark and Darker
- структура забега и карта выбора — Slay the Spire, Hades, Inscryption
- ощущение боя, i-frames, телеграф — Hades, Hollow Knight, Dead Cells, Souls-серия
- рост сложности по глубине — Risk of Rain 2, Slay the Spire act scaling
- экономика хаба, стоимости апгрейдов — Hades (Зеркало), Dead Cells, Rogue Legacy

**Результат:** `docs/prototype/ANSWERS-v0.1.md`. На каждый вопрос:
выбранный вариант · ≥2 внешних источника со ссылками · почему именно он для нас ·
цена разворота · **чем проверяется в билде** (какой ползунок, какой замер).

Плюс в `docs/design/OPEN-QUESTIONS.md` (только в этой ветке) статус меняется
на `гипотеза-прототипа` со ссылкой на ANSWERS. **Не** на `решён` — `решён` означает
ответ владельца, и это различие нельзя размывать.

**Готово, когда:** 14 из 14 закрыты, ни одного «зависит от», у каждого есть источники
и способ проверки. Числовой пакет Q-14 задаёт стартовые значения — не финальные.

**Не делать:** не трогать `SPEC-01…04`, `docs/adr/`, `README.md`.

## T-02 — Каркас и пайплайн сборки

**Зачем.** Без состояния и сейвов нельзя замкнуть петлю, без экспорта владелец ничего
не потрогает. Это единственный «скучный» таск — дальше только геймплей.

**Что сделать.**
- Автолоады: `GameState`, `EventBus`, `SeedService` — без `class_name` (ADR-005).
- Состояния раздельно, без God object: `RunState`, `HubState`, `ProfileState`.
- `SaveManager`: JSON через `FileAccess`, атомарная запись, 3 слота, бэкап,
  типизированный DTO-слой на чтение (ADR-003). Настройки — `ConfigFile`.
- Сид: мастер-сид ≤ 2^53−1, суб-сиды выводятся, не хранятся (ADR-004).
- `export_presets.cfg` под Windows + `tools/build.cmd` одной командой.

**Готово, когда:** headless-импорт без ошибок · тест save/load round-trip зелёный
(состояние после загрузки идентично) · `build.cmd` даёт запускающийся `.exe`.

**Не делать:** ни геймплея, ни арта. Заглушка вместо сцены — норма.

## T-03 — Бой и панель тюнинга ← первая сборка, которую щупают

**Зачем.** Q-02 и Q-03 — про **ощущение**. Их нельзя закрыть текстом. Владелец
получает ползунки и за 20 минут отвечает на них руками.

**Что сделать.**
- Скаут: `CharacterBody2D`, движение WASD, дэш с окном неуязвимости, атака.
- Враг: FSM с телеграфом по решению Q-02, урон, смерть, простое преследование.
- Камера, попадания, смерть скаута.
- Базовый game feel по практикам жанра: hit-stop, screenshake, буфер ввода.
- **Debug-панель по F1:** ползунки на i-frames дэша, кулдаун дэша, длину телеграфа,
  урон, HP, скорость. Значения применяются на лету, состояние панели сохраняется.

**Готово, когда:** есть `.exe`, в котором можно минуту драться, крутить ползунки
и почувствовать разницу. В отчёте — какие значения агент считает дефолтом и почему.

**Закрывает руками владельца:** Q-02, Q-03.

## T-04 — Экспедиция

**Что сделать.** Граф узлов по решению Q-01 · навигация выбором из 2–3 вариантов ·
типы узлов: бой, ресурс, событие, безопасный лагерь, эвакуация, элита, страж ·
добровольная эвакуация с порогом (Q-06) · смерть и потери (Q-05) ·
стабильная и нестабильная добыча · элитный узел (Q-12) · Guardian (Q-13) ·
воспроизводимость по сиду.

**Готово, когда:** полный забег проходится от входа до эвакуации или смерти,
результат корректно ложится в `RunState` и переживает сохранение;
один и тот же сид даёт одну и ту же карту.

**Закрывает:** Q-01, Q-05, Q-06, Q-12, Q-13 (реализация решений из T-01).

## T-05 — Хаб и экономика ← петля замыкается

**Что сделать.** Экран хаба, Маяк, 4 фиксированных сокета (Q-10) ·
Кузница с 3 уровнями, у каждого свой минус (Q-07) · стоимости (Q-08) ·
Свет как ресурс/место (Q-09) · трата Материалов · Память как валюта разблокировок ·
модули **меняют правила экспедиции**, а не только числа.

**Готово, когда:** цикл замкнут — забег → добыча → постройка → следующий забег
**ощутимо другой**. Это главный критерий: если модуль не меняет игру, он не сделан.

**Закрывает:** Q-07, Q-08, Q-09, Q-10.

## T-06 — Headless-симулятор и калибровка чисел

**Зачем.** Q-04, Q-11, Q-14 — не про вкус, а про цифры. Их закрывает замер,
а не мнение. Тысяча прогонов дешевле часа спора.

**Что сделать.** Скрипт-симулятор забегов без графики с ботом-политикой
(жадный / осторожный / случайный). Печатает: доля успешных эвакуаций по глубине,
средняя и медианная добыча, дисперсия, фактическая длина забега в минутах,
проверка кривой K(d).

**Готово, когда:** `godot.cmd --headless --script tools/sim.gd -- --runs 1000`
печатает таблицу · числовой пакет Q-14 **подобран по замерам**, а не выдуман ·
в отчёте видно, где предположения T-01 не подтвердились.

**Закрывает:** Q-04, Q-11, Q-14.

## T-07 — Полировка, сборка v0.1 и отчёт

**Что сделать.** Полировка ощущения по итогам T-03…T-06 · главное меню → хаб →
экспедиция → возврат без разрывов · финальная Windows-сборка ·
`docs/prototype/REPORT-v0.1.md`.

**Отчёт должен честно разделять три вещи:**
1. что подтвердилось замером,
2. что выбрано по практике жанра, но не проверено,
3. что осталось на вкус владельца и ждёт его рук.

**Готово, когда:** `.exe` запускается с чистой машины и проходится целиком,
отчёт написан, ветка запушена.
