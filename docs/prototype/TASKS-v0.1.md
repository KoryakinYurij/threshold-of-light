# Прототип v0.1 — карта работ

Ветка: `proto/v0.1`. **Один таск = один чат.**

> Это не вейфайндер-карта. Вейфайндер производит решения и требует живого участия
> владельца в каждом тикете; здесь производится сборка, и владелец сознательно вышел
> из цикла до момента, когда будет что пощупать. Из вейфайндера взята только форма:
> пункт назначения, журнал сделанного, фог-секция и области вне работы.

---

## Пункт назначения

Владелец запускает `.exe`, играет и **обретает мнение**: что нравится, что нет, как он
на самом деле хочет. Сейчас мнения нет, потому что не с чем сверяться — 14 дизайн-развилок
висят нерешёнными именно поэтому. Прототип существует ради этого мнения, а не ради кода.

Каждый чат сверяется с этой строкой перед тем, как что-то делать. Если действие не
приближает владельца к «я это потрогал» — оно лишнее.

## Заметки

- Прототип **одноразовый**. В `master` не мержится. Обратно поедут только выводы.
- Жанр: 2D hub-builder + extraction-lite + action-roguelite, Godot 4.7.1, Compatibility.
- Скиллы под рукой: `.agents/skills/godot-*` (50 штук), `/prototype`, `/tdd`,
  `/diagnosing-bugs`, `/code-review`.
- Опорные документы: `CONTEXT.md`, `docs/specs/SPEC-01…04`, `docs/adr/`,
  `docs/design/OPEN-QUESTIONS.md`, три supplement'а в `docs/research/`.

## Правила для всех чатов по этой ветке

1. **Владельца не спрашивать.** Упёрся в блокер — идёшь в интернет, смотришь, как это
   решают профессиональные геймдевы в шипнутых играх, выбираешь по балансу
   качество/трудозатраты, записываешь решение с источниками. Не «на усмотрение
   владельца», не «оставим TODO».
2. **Ветка одна — `proto/v0.1`.** В `master` ничего не мержим.
3. **Начиная с «Каркаса и сборки» каждый таск заканчивается свежим `.exe`.**
4. **Godot:** `D:\Tools\Godot\4.7.1\godot.cmd`, работа `--headless` — MCP-сервер
   `godot-mcp` по SSH недоступен, экрана агент не видит. Визуальная проверка на владельце.
5. **Удалённый шелл — cmd.exe:** heredoc не работает, `git commit` только через `-m`
   или `-F`; файлы класть через `scp`, не через Write. `chcp 65001` перед Godot,
   иначе русские логи поедут.
6. **Соблюдать:** ADR-003 (JSON: каждое целое поле кастовать явно), ADR-004 (мастер-сид
   ≤ 2^53−1), ADR-005 (автолоады **без** `class_name`), именование из `CONTEXT.md`.
7. **Каждый таск — коммит с внятным сообщением.** Незавершённый таск не закрывать.
8. **Завершение таска — обязательный ритуал.** Прежде чем сказать «готово», агент:
   - дописывает строку в раздел **Сделано** этого файла (одна строка: что решено/сделано,
     ссылка на артефакт — не пересказ, а указатель);
   - переносит из **Ещё не уточнено** в таски всё, что после этого таска стало
     формулируемым, и вычёркивает оттуда перенесённое;
   - коммитит и пушит;
   - **последним сообщением в чате выдаёт handoff-сообщение по шаблону ниже** — готовое
     к копированию в новый чат. Не пересказ работы, а рабочий вход для следующего агента.

## Таски

### T-01 «Ответы через ресёрч»

**Зачем.** Всё остальное заблокировано `docs/design/OPEN-QUESTIONS.md`: 13 вопросов
`открыт`, один `калибровка`. Владелец ответить не может. Значит отвечает ресёрч.

**Что сделать.** По каждому Q-01…Q-14 найти, как эту развилку решают в шипнутых играх
жанра, и выбрать. Ориентиры для поиска (не догма, ищи шире):

- потери при смерти, extraction risk/reward — Hunt: Showdown, Escape from Tarkov, Dark and Darker
- структура забега и карта выбора — Slay the Spire, Hades, Inscryption
- ощущение боя, i-frames, телеграф атаки — Hades, Hollow Knight, Dead Cells, Souls-серия
- рост сложности по глубине — Risk of Rain 2, act scaling в Slay the Spire
- экономика хаба и стоимости — Hades (Зеркало), Dead Cells, Rogue Legacy

**Результат:** `docs/prototype/ANSWERS-v0.1.md`. На каждый вопрос: выбранный вариант ·
≥2 внешних источника со ссылками · почему именно он для нас · цена разворота ·
**чем проверяется в билде** (какой ползунок, какой замер).

Плюс в `docs/design/OPEN-QUESTIONS.md` (только в этой ветке) статус меняется на
`гипотеза-прототипа` со ссылкой. **Не** на `решён` — `решён` означает ответ владельца,
и это различие размывать нельзя.

**Готово, когда:** 14 из 14 закрыты, ни одного «зависит от», у каждого источники и способ
проверки. Числовой пакет Q-14 задаёт стартовые значения, не финальные.

**Не делать:** не трогать `SPEC-01…04`, `docs/adr/`, `README.md`.

### T-02 «Каркас и сборка»

**Зачем.** Без состояния и сейвов не замкнуть петлю, без экспорта владельцу нечего трогать.
Единственный скучный таск — дальше только геймплей.

**Что сделать.**
- Автолоады: `GameState`, `EventBus`, `SeedService` — без `class_name` (ADR-005).
- Состояния раздельно, без God object: `RunState`, `HubState`, `ProfileState`.
- `SaveManager`: JSON через `FileAccess`, атомарная запись, 3 слота, бэкап,
  типизированный DTO-слой на чтение (ADR-003). Настройки — `ConfigFile`.
- Сид: мастер-сид ≤ 2^53−1, суб-сиды выводятся, не хранятся (ADR-004).
- `export_presets.cfg` под Windows + `tools/build.cmd` одной командой.

**Готово, когда:** headless-импорт без ошибок · тест save/load round-trip зелёный ·
`build.cmd` даёт запускающийся `.exe`.

**Не делать:** ни геймплея, ни арта. Заглушка вместо сцены — норма.

### T-03 «Бой и ползунки» ← первая сборка, которую щупают

**Зачем.** Q-02 и Q-03 — про **ощущение**, текстом их не закрыть. Владелец получает
рычаги и за 20 минут отвечает на них руками.

**Что сделать.**
- Скаут: `CharacterBody2D`, движение WASD, дэш с окном неуязвимости, атака.
- Враг: FSM с телеграфом по решению Q-02, урон, смерть, простое преследование.
- Камера, попадания, смерть скаута.
- Game feel по практикам жанра: hit-stop, screenshake, буфер ввода.
- **Панель по F1:** ползунки на i-frames дэша, кулдаун дэша, длину телеграфа, урон, HP,
  скорость. Применяются на лету, состояние панели сохраняется.
- **Счётчики боя:** выпущено снарядов / попало, полученный урон, время узла. Пишутся
  в лог по `node_cleared`. Из них T-06 берёт `hit_rate` — единственную ручку
  калибровки пакета Q-14 (`ANSWERS-v0.1.md` §Q-14).

**Дефолты берутся из `ANSWERS-v0.1.md` §Q-14, не из `SPEC-04`:** дэш 0.30 c,
i-frames 0.30 c, кулдаун дэша 0.55 c, телеграф 0.45 c, HP Преследователя 50.

**Готово, когда:** есть `.exe`, в котором можно минуту драться и почувствовать разницу
от ползунков. В отчёте — какие значения агент считает дефолтом и почему.

**Закрывает руками владельца:** Q-02, Q-03.

### T-04 «Экспедиция»

**Что сделать.** Граф узлов по решению Q-01 · навигация выбором из 2–3 вариантов ·
типы узлов: бой, ресурс, событие, безопасный лагерь, эвакуация, элита, страж ·
добровольная эвакуация **без счётчика-порога**: вместо него инвариант G3′ — `EXTRACTION`
не выпадает в ряду 1 (Q-06) · смерть и потери (Q-05) · стабильная
и нестабильная добыча · элитный узел, помеченный на карте до входа (Q-12) ·
Guardian с фазой на 50 % HP (Q-13) · воспроизводимость по сиду.

**Готово, когда:** забег проходится от входа до эвакуации или смерти, результат корректно
ложится в `RunState` и переживает сохранение; один сид даёт одну и ту же карту.

**Закрывает:** Q-01, Q-05, Q-06, Q-12, Q-13.

### T-05 «Хаб и экономика» ← петля замыкается

**Что сделать.** Экран хаба, Маяк, 4 фиксированных сокета (Q-10) · Кузница с 3 уровнями,
у каждого свой минус (Q-07) · стоимости (Q-08) · Свет (Q-09) · трата Материалов ·
Память как валюта разблокировок · модули **меняют правила экспедиции**, а не только числа.

**Готово, когда:** цикл замкнут — забег → добыча → постройка → следующий забег
**ощутимо другой**. Это главный критерий: если модуль не меняет игру, он не сделан.

**Закрывает:** Q-07, Q-08, Q-09, Q-10.

### T-06 «Симулятор и калибровка»

**Зачем.** Q-04, Q-11, Q-14 — про цифры, а не про вкус. Тысяча прогонов дешевле часа спора.

**Что сделать.** Симулятор забегов без графики с ботом-политикой (жадный / осторожный /
случайный). Печатает: долю успешных эвакуаций по глубине, среднюю и медианную добычу,
дисперсию, фактическую длину забега в минутах, проверку кривой K(d).

**Повторяемые замеры и пороги приёмки** (перенесено из «Ещё не уточнено» — после T-01
это стало формулируемым; полные обоснования в `ANSWERS-v0.1.md`):

| Замер | Порог | Вопрос |
|---|---|---|
| Медиана времени боевого узла по глубинам d=1…6 | 25 c → 55 c, монотонно, ни один узел вне 20–70 c | Q-04 |
| `T(6) / T(1)` | 2.0–2.6 | Q-11 |
| Доля забегов, законченных добровольной эвакуацией | 40–60 % | Q-05 |
| Медиана элитного узла / медиана боевого на той же глубине | ≤ 1.5 | Q-12 |
| Длительность узла Guardian / медиана боевого узла на d=6 | ≤ 2.0 | Q-13 |
| Медиана боевого узла при Кузнице ур.2 vs ур.1 | ур.2 ≤ ур.1 | Q-07 |
| Забегов до Кузницы ур.2 / ур.3 | 2–3 / 5–6 | Q-08 |
| `hit_rate` = попало / выпущено | замер, не порог — из него пересчитывается `enemy_hp_base` | Q-14 |

**Готово, когда:** `godot.cmd --headless --script tools/sim.gd -- --runs 1000` печатает
таблицу · пакет Q-14 **подобран по замерам**, не выдуман · в отчёте видно, где
предположения T-01 не подтвердились.

**Закрывает:** Q-04, Q-11, Q-14.

### T-07 «Полировка и v0.1»

**Что сделать.** Полировка ощущения по итогам T-03…T-06 · главное меню → хаб →
экспедиция → возврат без разрывов · финальная Windows-сборка ·
`docs/prototype/REPORT-v0.1.md`.

**Отчёт честно разделяет три вещи:** что подтвердилось замером · что выбрано по практике
жанра, но не проверено · что осталось на вкус владельца и ждёт его рук.

**Готово, когда:** `.exe` запускается с чистой машины и проходится целиком, отчёт написан,
ветка запушена.
